# 知识库 RAG 设计

> 本文档定义思忆集的个人知识库检索增强生成（RAG）系统。
> 知识库与记忆层的核心区别：知识库存储**外部信息**（文档、网页、笔记），记忆层存储**个人经历与偏好**。

## 参考对标

| 产品 | 借鉴点 |
|------|--------|
| **Dify** | 开源 RAG pipeline：分段策略、检索模式（向量/全文/混合）、重排序 |
| **Perplexity** | 检索增强对话体验、来源引用展示 |
| **Coze** | 知识库管理界面、文档自动同步、分段预览 |
| **ChatGPT Memory** | 简洁的用户体验：不暴露 chunk/vector 等技术概念 |

## 1. 知识库架构总览

```
┌─────────────────────────────────────────────┐
│  摄入层 (Ingestion)                          │
│  ├─ 浏览器桥接：网页正文提取 → 知识库          │
│  ├─ 文件拖拽：PDF/Markdown/TXT → 解析入库     │
│  ├─ 笔记联动：笔记可标记"纳入知识库"           │
│  └─ RSS 自动抓取：新闻/博客 → 定时入库         │
├─────────────────────────────────────────────┤
│  处理层 (Processing)                         │
│  ├─ 文档解析：PDF/Markdown/HTML → 纯文本      │
│  ├─ 智能分段：按语义边界切 chunk               │
│  ├─ 向量化：sentence-transformers → ChromaDB  │
│  └─ 元数据提取：标题、来源、日期、标签          │
├─────────────────────────────────────────────┤
│  检索层 (Retrieval)                          │
│  ├─ 混合检索：向量相似度 + BM25 关键词         │
│  ├─ 重排序：cross-encoder 精排                │
│  └─ 来源过滤：按文档/时间/标签过滤              │
├─────────────────────────────────────────────┤
│  生成层 (Generation)                         │
│  ├─ 上下文组装：检索结果 + 对话历史 + 记忆      │
│  ├─ 来源引用：每个回答附带引用来源              │
│  └─ 缓存：相同查询 24h 内复用结果              │
└─────────────────────────────────────────────┘
```

## 2. 文档摄入

### 2.1 支持格式

| 格式 | 优先级 | 解析方式 |
|------|--------|---------|
| Markdown | P0 | 直接分段 |
| 纯文本 | P0 | 直接分段 |
| HTML（网页） | P0 | bleach 清洗 → Markdown |
| PDF | P1 | PyMuPDF / pdfplumber |
| 图片 OCR | P2 | 暂不实现 |

### 2.2 摄入入口

| 入口 | 触发方式 | 说明 |
|------|---------|------|
| 浏览器扩展 | 用户点击"保存到思忆集" | 提取当前页正文，清洗后入库 |
| 桌面拖拽 | 拖文件到悬浮助手/主窗口 | 自动识别格式并解析 |
| 笔记转存 | 笔记中勾选"纳入知识库" | 笔记内容作为知识库条目 |
| RSS 自动 | 定时任务抓取 | 新闻/博客源自动更新 |

### 2.3 网页正文提取

参考 Perplexity 的阅读模式，浏览器扩展负责：
- 通过 Readability 算法提取正文
- 去除广告、导航、侧边栏
- 保留原始 URL 和时间戳作为元数据
- HTML 清洗已在 `requirements-desktop.txt` 中纳入 `bleach`

## 3. 分段与向量化

### 3.1 分段策略

```
chunk_size: 512 tokens（中文约 800 字）
chunk_overlap: 64 tokens（中文约 100 字）
分段优先级: 按段落边界 > 按句子边界 > 按固定长度截断
```

保留上下文窗口：检索时，每个命中 chunk 自动带上前后各 1 个 chunk。

### 3.2 Embedding 模型

当前方案（开发期）：
- 模型：`sentence-transformers`（已集成在 `requirements-desktop.txt`）
- 推荐模型：`BAAI/bge-small-zh-v1.5`（中文优化，轻量本地运行）
- 维度：512

后续可选升级：
- `BAAI/bge-large-zh-v1.5`（更高精度）
- 云端 embedding API（弱网降级到本地）

### 3.3 向量存储

- 引擎：ChromaDB（已集成）
- 持久化：本地磁盘，路径 `data/chroma/`
- 同步策略：向量索引不跨设备同步（各端独立构建），只同步原始文档

## 4. 检索策略

### 4.1 混合检索

```
用户查询
  ├─ 向量检索 (ChromaDB): top_k=20, 相似度阈值 0.6
  ├─ 关键词检索 (BM25): top_k=10
  └─ 合并去重 → 重排序 (cross-encoder) → 取 top_k=5
```

### 4.2 重排序

- 模型：`cross-encoder/ms-marco-MiniLM-L-6-v2`（轻量）
- 输入：(query, chunk) 对
- 输出：相关性分数 0-1
- 取 top 5 送入 LLM 上下文

### 4.3 过滤与安全

- 用户可在检索时指定过滤条件：文档来源、日期范围、标签
- 检索结果附带元数据来源标签：`[知识库: 文档名]`
- 敏感文档可标记"不送模型"，仅本地检索可见

## 5. 与记忆层的上下文组装

LLM 调用时的上下文组装顺序：

```
System Prompt
  ├─ 用户画像摘要（偏好 + 关键身份信息）
  ├─ 相关记忆（最近 5 条，从记忆层检索）
  ├─ 相关知识库条目（最多 3 条，从知识库检索）
  └─ 对话历史（最近 N 轮）

User Message
  └─ 当前查询
```

每条上下文附带来源标记，LLM 被指示在回答中引用来源。

## 6. 缓存与性能

### 6.1 查询缓存

- 相同查询（语义去重后）24h 内复用结果
- 缓存命中时跳过 embedding + 检索，直接返回
- 知识库更新时，相关查询缓存失效

### 6.2 索引更新策略

| 触发条件 | 更新方式 |
|---------|---------|
| 新增文档 | 增量更新：只 embed 新 chunk |
| 删除文档 | 标记删除，定期清理向量 |
| 批量导入 | 全量重建该文档集合的索引 |

## 7. 实现路线

| 阶段 | 内容 | 预估 |
|------|------|------|
| Phase 0 | 浏览器桥接 → 正文提取 → 纯文本分段 → ChromaDB 存入 | 2 周 |
| Phase 1 | 向量检索 + 简单关键词 → 上下文组装 → 来源引用展示 | 2 周 |
| Phase 2 | 混合检索（BM25）+ 重排序（cross-encoder） | 1 周 |
| Phase 3 | 多格式摄入（PDF）+ 自动标签 + 知识库管理 UI | 2 周 |
