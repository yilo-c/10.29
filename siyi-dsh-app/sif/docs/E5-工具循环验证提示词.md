# E5 真实工具循环验证 · 操作说明

## 为什么要单独做这一步

现在工具已经注册（日志确认 6/6），但**「注册成功」不等于「模型真的会调用」**。

E5 的定义是：

> 模型发工具调用 → 工具执行 → 结果回到模型 → 模型再请求并给出最终回答

只看到工具在清单里、或只看到日志说注册了，都只是 E3/E4。必须观察到完整回路才算 E5。

## 怎么做

### 前提

当前会话（40 万 token）不适合做这个验证，原因：

1. 上下文太大，第三方渠道可能崩
2. 旧会话里没有新工具的定义，模型看不到

**开一个新会话**，然后粘贴下面的提示词。

### 验证提示词（直接复制）

```
请用工具帮我查一下知识库。

要求：
1. 必须调用 vault_search 工具搜索关键词「知识」，不要用 glob、grep、read 去翻目录
2. 从结果里挑一篇，调用 vault_get 读取它的完整内容
3. 最后告诉我：标题、标签、双链、以及那篇笔记的 revision（64 位十六进制）

如果 vault_search 或 vault_get 不可用，直接告诉我工具不存在，不要绕路。
```

### 期望观察到的完整回路

1. 模型发起 `vault_search` 调用，参数含 `q: "知识"`
2. 工具返回结构化列表（形如「共 N 篇，显示前 N 篇：- 标题 [kind] id=...」）
3. 模型发起 `vault_get` 调用，参数含上一步返回的 id
4. 工具返回笔记正文、标签、双链、revision
5. 模型给出最终自然语言回答

### 判定标准

| 观察项 | 通过 | 不通过 |
|---|---|---|
| 调用了 vault_search | 是 | 用了 glob/grep 翻目录 |
| 返回结构化列表 | 是 | 报错或空 |
| 调用了 vault_get | 是 | 跳过或伪造 |
| 返回 64 位 revision | 是 | 没有 |
| 给出最终回答 | 是 | 只说「工具不可用」 |

### 如果不通过

按以下顺序排查：

1. **工具不存在** → 检查 `grep -a 'siyi-vault-tools' /storage/emulated/0/思忆集/app/engine-stderr.log`，确认 6/6
2. **工具存在但模型不用** → 可能是工具描述不够清楚，或模型倾向用熟悉的 glob/grep
3. **调用报错** → 看引擎 stderr 里的 `[siyi-vault-tools]` 日志

### 通过后要记录什么

把以下内容写进 `config/current-state.json` 的 `E5` 字段：

- 会话 id
- 时间
- 调用链（工具名序列）
- 返回的 revision 值
- 模型最终回答的摘要

这样才算把证据等级从 E4 升到 E5。

## 与 E4 的区别

| 等级 | 含义 | 当前状态 |
|---|---|---|
| E3 | 隔离进程 / 真实 defineTool 校验 | 已通过（8 项） |
| E4 | 真实宿主 + 真实系统能力（HTTP 端到端） | **已通过**（列表/读取/统计/文件夹/路径拦截） |
| E5 | 真实模型完整工具循环 | **待做** |

E4 证明了「能力可用」，E5 才能证明「模型会用」。
