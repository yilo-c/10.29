## 一、结论先说

**工具确实被真实调用了，但模型看到的输出是错的。** 根因是 vault 工具适配器的
`output.render` 签名写错：宿主给的是 `(args, value)`，插件按 `(value)` 接，
于是「入参被当成结果」渲染：

- `vault_search q=知识` → 模型看到「没有匹配的笔记（共 0 篇）」
- `vault_get id=<真实笔记>` → 模型看到空标题、`revision: undefined`、无正文
- `vault_stats` → 「共 undefined 篇」

`execute` 本身返回的数据是正确的（搜索 4 篇、读取 56 篇中的真实笔记都正常），
坏的只是「结果→模型可见文本」这一层。这正是 E5 要抓的问题：
**工具链两端都通，中间表示层断了，靠 HTTP 验证和单元测试都发现不了。**

## 三、根因

`@deepseek-ai/dsh-tools` 的 `defineTool` 内部：

```js
output: {
  schema: outputSchema,
  render(args, value) { return userRender(args, value); },
}
```

即宿主按 `render(args, value)` 调用。插件原写法：

```js
render: (value) => renderValue(toolName, value)   // 错：第一个参数是 args
```

修复：

```js
render: (_args, value) => renderValue(toolName, value)   // 对
```

## 四、为什么 86 项测试没抓到

`dsh-adapter.test.mjs` 的两项 render 测试按单参数调用：
`output.render({ total: 0, items: [] })` —— 等于把旧错误签名写进了断言，
插件错了测试反而绿。和 06:45 文档里「桩测试发现不了宿主方言问题」同类：
**测试的调用约定必须对齐真实宿主**，否则测的是自己想象的世界。

已修：

- 两项 render 测试改为 `render(args, value)`，并注明宿主契约
- 插件内加注释说明首参是入参、次参才是返回值
