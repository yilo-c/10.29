### 修复过程中发现的第二个真实 bug

第一版 `assertInsideVault` 用 `realpath(VAULT)` 前缀比较，结果正常新建全部报「路径越界」。

根因：Android 上 `/data/user/0` 是指向 `/data/data` 的符号链接。调用方传入的路径是 `/data/user/0/...`（未规范化），而 `realpath(VAULT)` 返回 `/data/data/...`，字符串前缀必然不匹配。

修正：取「最近的已存在祖先」做 realpath，再把尚未存在的尾段拼回去。这样既处理根路径符号链接，也能在文件尚未创建时判断归属。

13 项回归测试暴露了这个 bug，修复后全部通过。

## 七、追加：vault 能力注册为 DSH 工具（2026-11-18 06:05）

### 做了什么

新增 DSH 适配器插件，把 6 个中立 vault 能力投影成 DSH 工具。

- 源文件：`sif/plugins/siyi-vault-tools.js`
- 已部署：`/storage/emulated/0/思忆集/plugins/siyi-vault-tools.js`
- 测试：`sif/tests/contract/dsh-adapter.test.mjs`（12/12 通过）

工具名（DSH 不允许点号，已转换）：

```
vault.get      → vault_get
vault.search   → vault_search
vault.save     → vault_save
vault.trash    → vault_trash
vault.stats    → vault_stats
vault.reconcile→ vault_reconcile
```

### 三个关键设计决定

**1. 用静态 import，不用 apply 内异步加载**

加载器用动态 `import()` 且不 await `apply()`。若在 apply 里异步注册，会出现「日志已加载、工具还没注册完」的竞态。静态 import 在模块求值阶段完成，apply 时同步注册。

**2. 用绝对路径 import**

`/sdcard/思忆集/plugins` 不在 Node 模块解析路径上，无法用裸包名。已实测绝对路径静态 import 在 Android Node 24 可用。

**3. 复用 sif 的 VaultService，不重写**

HTTP（siyi-vault.js）和 AI 工具必须是同一个写入实现，否则两条路径会产生不同的 frontmatter、不同的路径校验、不同的原子写行为。

### 适配器做的工作

中立 schema（标准 JSON Schema，`required` 是数组）→ DSH 方言（`required` 写在字段内部）。这个转换只存在于适配器，不污染核心契约。
