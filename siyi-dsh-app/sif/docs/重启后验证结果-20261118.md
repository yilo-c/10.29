## 三、vault 工具插件：发现真实 bug，已修复但需再次重启

### 3.1 首次加载只成功 3/6

```
[siyi-vault-tools] warn: 注册 vault.save 失败:
  unsupported JSON schema: parameters.expectedRevision.pattern
  is not supported by the value schema DSL
[siyi-vault-tools] 已注册 3/6 个 vault 工具
```

### 3.2 根因（已读源码确认）

`@deepseek-ai/dsh-tools/lib/types/schema.js` 的 `assertAuthorKeys` 有严格白名单：

| 类型 | 允许的键 |
|---|---|
| string | `type` `enum` `const` |
| integer | `type` `enum` `const`（**无 minimum/maximum**）|
| object | `type` `properties` `additionalProperties` |
| array | `type` `items` |
| 通用注释 | `description` `title` `default` `examples` |

出现白名单外的键（`pattern`、`minimum`、`maximum`、`format`）就抛错，**整个工具注册失败**。

### 3.3 修复方式

不是改中立契约去掉 `pattern`，而是在**适配器**里剥离：

- 中立契约保留 `pattern` 等约束（这是跨宿主的能力描述）
- 适配器投影到 DSH 时剥离这些键
- 校验职责交给 `execute` 里的业务代码（VaultService 的 ULID 检查确实会执行）

这符合分层原则：中立契约不迁就任何宿主方言。

### 3.4 修复后验证（用真实 defineTool，不是桩）

```

PASS 每个工具都通过 defineTool 的 schema 编译

PASS required 正确转成标准数组
PASS 数组字段结构正确
PASS 工具描述含风险标注
PASS 真实调用仍可用（schema 裁剪不影响执行）
PASS 业务层仍拒绝非法 id（pattern 剥离后靠 execute 校验）
TOTAL 8  PASS 8  FAIL 0
```

同时发现 `defineTool` 会把 parameters 重新编译成标准 JSON Schema（`required` 变回数组），第一版测试断言写错，已修正。

### 6.6 本轮最有价值的两条经验

`dsh-adapter.test.mjs` 用桩 `defineTool` 测了 12 项全通过，但真实引擎只注册成功 3/6。原因是桩不校验 schema 方言。补上 `dsh-schema-dsl.test.mjs`（用真实 `defineTool`）才发现问题。

教训：任何「补丁已部署」的说法，都要附上「运行实例是否已更新」的独立证据。
