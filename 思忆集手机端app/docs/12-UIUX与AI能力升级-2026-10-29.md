## 一、修掉的布局问题

### 1.1 底部导航吃掉 1/6 屏幕（根因）

**原代码**（`App.tsx:189-200`）：

```tsx
paddingTop: 8,
paddingBottom: 'calc(env(safe-area-inset-bottom, 0px) + 48px)',  // ← 硬加 48px
minHeight: 90,
```

导航栏实际渲染高度 ≈ 8 + 22(图标) + 2(gap) + 12(文字) + 48 + 安全区 ≈ **92px + 安全区**，
在一台 6.7 寸手机上约占屏幕高度的 12%。加上 `overflowX: auto` 让 5 个按钮挤在可横向滚动的容器里，
视觉上显得散乱。

**改为**（`layout.css`）：

```css
--tabbar-height: 50px;
.tabbar { height: calc(var(--tabbar-height) + var(--safe-bottom)); }
```

50px + 安全区，是 iOS/Android 原生 tab bar 的标准高度。同时用 `grid-auto-columns: 1fr`
让 5 个按钮等分，不再横向滚动。

### 1.2 flex 布局溢出

```tsx
<main style={{ flex: 1, overflow: 'hidden' }}>   // ← 缺 min-height: 0
```

flex 子项默认 `min-height: auto`，内容撑高时不会收缩，导致页面底部的 FAB 被顶出可视区。
`layout.css` 里 `.app-main` 补上 `min-height: 0`。

### 1.3 内联 style 无法统一维护

原来 60+ 个组件全用内联 style，同一个「页面头部」在 5 个 Tab 里各写一遍，padding 都不一样。
新建 `styles/layout.css`（168 行）提供语义化类：

| 类名 | 用途 |
|---|---|
| `.app-shell` / `.app-main` | 应用骨架 |
| `.page` / `.page--hidden` / `.page-scroll` | 页面容器与滚动区 |
| `.page-header` / `.page-header__title` | 统一页面头部 |
| `.page-body` / `.page-body--tight` | 统一内边距 |
| `.tabbar` / `.tabbar__item` / `.tabbar__fab` | 底部导航 |
| `.toolbar` / `.tool-btn` | 工具条 |
| `.card` / `.row` / `.stack` | 基础布局原语 |
| `.fab` / `.empty-state` | 浮动按钮、空状态 |

`.page-scroll` 统一留出 `padding-bottom: calc(var(--tabbar-height) + var(--space-4))`，
从此不会再出现「最后一条内容被导航栏盖住」。

## 二、AI 在导航中的位置调整

**原布局**：`待办 | 笔记 | AI | 工具 | 设置`，AI 是普通按钮，20px 图标 + 10px 文字。

**现布局**：AI 移到正中，改为**抬起的主按钮**：

```css
.tabbar__item--primary .tabbar__fab {
  width: 46px; height: 46px; border-radius: 9999px;
  background: var(--accent); color: #fff;
  box-shadow: var(--shadow-fab);
  transform: translateY(-14px);
}
```

理由：AI 是这个 App 的核心差异点，但原设计里它和「设置」平级，视觉权重相同。
中央 + 抬起 + 强调色，让「随时唤起 AI」变成拇指肌肉记忆。

## 三、补齐的缺失文件

仓库上传时遗漏了 5 个源文件，导致**手机端原本无法编译**。本次按后端接口反推实现：

| 文件 | 来源依据 | 行数 |
|---|---|---|
| `components/ui/ErrorBoundary.tsx` | 全新实现 | 158 |
| `lib/bridges/infoBridge.ts` | `_info_items.py` / `_info_sources.py` / `_info_proxy.py` | 392 |
| `lib/bridges/cronBridge.ts` | `_cron.py`（9 个方法） | 138 |
| `lib/bridges/agentBridge.ts` | `_agent_tasks.py`（10 个方法） | 136 |
| `lib/bridges/auditBridge.ts` | `_audit.py`（7 个方法） | 141 |

**注意**：`agentBridge` 与 `cronBridge`/`auditBridge` 都有 `history`、`runNow` 同名函数，
`export *` 会冲突（TS2308）。`bridges/index.ts` 改为命名空间导出：

```ts
export * as cron from './cronBridge'
export * as agent from './agentBridge'
export * as audit from './auditBridge'
```

调用方写 `cron.history()` / `agent.cancel()`，语义更清楚。

### ErrorBoundary 的设计取舍

手机上每个 Tab 都常驻挂载（P1-18 优化），**任何一个 Tab 渲染抛错会让整棵树卸载 → 白屏**，
用户连切 Tab 自救都做不到。因此每个 Tab 独立包 ErrorBoundary：

- 「重试」→ 重置状态重新挂载子树
- 「复制错误」→ 方便贴出来排查
- 不自动上报网络，避免把用户数据带出去

## 四、AI 能力提升（重点）

### 4.1 发现问题：隐私分级实际没生效

`assistantRuntime.ts`（173 行）写得很完整：意图分类、隐私分级、六个目标的路由、离线缓存。
**但全仓库没有任何文件 import 它**：

```
$ grep -rn "assistantRuntime" src/ | grep -v "assistantRuntime.ts:"
（空）
```

真实链路在 `mobileStore.sendMessage` 里另写了一套简化逻辑，**完全没有隐私判断**。
后果：用户开启云 AI 后，`我的日记`、`密码是 xxx` 这类内容会直接发到云端。

### 4.2 发现更深的问题：aiRouter 的 SYNCABLE 语义错误

试图接入时测试暴露了原设计的致命缺陷（`aiRouter.ts:153`）：

```ts
const isPrivate = privacyLevel === LOCAL_ONLY || privacyLevel === SYNCABLE
if (isPrivate && !isDesktopConnected) return AiTarget.QUEUED_PENDING
```

`classifyPrivacy` 默认把所有内容判为 `SYNCABLE`，所以**只要桌面没连，包括「今天天气怎么样」在内的
所有问题都会排队**，云 AI 永远轮不上。这正是 `assistantRuntime` 当初被弃用的真正原因——
接上去聊天就废了。

**修正后的语义**：

| 等级 | 含义 | 路由 |
|---|---|---|
| `LOCAL_ONLY` | 含敏感词 | 只走桌面；桌面不在则排队，**绝不外发** |
| `SYNCABLE` | 自己的数据（默认） | 优先桌面；桌面不在且用户关掉了「发送前确认」→ 上云 |
| `SHAREABLE` | 可外发 | 受 `promptBeforeCloud` 控制 |
| `MODEL_EGRESS_ALLOWED` | 明确允许 | 直接上云 |

### 4.3 新增 ChatOrchestrator：把两条链路合成一条

`lib/chatOrchestrator.ts`（253 行）统一编排：

```
用户输入
  ↓
隐私分级 classifyPrivacy          ← 敏感内容强制本地
  ↓
本地工具匹配 matchTools           ← 命中即执行，零网络
  ↓
路由 resolveTarget
  ├─ 桌面 AI ──→ 流式；失败降级云（仅当允许外发）
  ├─ 云 AI   ──→ 流式；失败降级桌面
  └─ 都不可用 ──→ 查缓存 → 命中即返回；否则排队
```

**关键取舍**：

1. **隐私优先于可用性**：`LOCAL_ONLY` 内容即使云端可用也不发，明确告诉用户原因，
   而不是静默失败或偷偷上传。
2. **工具匹配不再依赖意图分类**。原逻辑只在 `intent === LOCAL_CRUD` 时才试工具，
   但意图分类用「创建/新建/添加」，工具标签是「记下来/提醒我」，两套词表不重合，
   导致「帮我把这段记下来」漏掉。现在工具直接先跑。
3. **缓存命中要标注来源**，不冒充实时回答。

### 4.4 聊天框实时隐私提示

用户打字时即刻显示：

```
🔒 含敏感内容 · 不会上传，仅在本机处理
```

用的是同一个 `orchestrator.inspect()`，避免 UI 与真实路由各写一套规则而漂移。

### 4.5 新增工具页（ToolsView）

原 `ToolsView` 缺失导致编译失败。新建 19KB 三栏面板，接入 7 个原生能力：

- **设备**：电量、网络、存储占用、内存占用、无障碍服务状态、Root 状态
- **自动化**：读屏、模拟点击滑动、已安装应用列表（可点击启动）
- **数据**：小米便签读取（需 Root）

设计要点：每个能力独立 `try/catch`，单项不可用不影响整页——手机端能力可用性差异很大，
必须逐项降级。
