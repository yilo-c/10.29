## 一、资讯模块：从「完全不能用」到「14 源直连」

### 1.1 为什么之前不能用（三个叠加原因）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **必须桌面端在线**才有内容 | `InfoView.refresh()` 里 `if (tokenManager.isPaired)` 才走 RPC；未配对时回退到 `collectAll()`，而它也走 RPC |
| 2 | **后端只有 2 个源** | `_info_proxy.py` 的 `SOURCES` 只有知乎热榜 + 微博热搜 |
| 3 | **回退链路本身是死的** | `collectAll()` → `infoBrief()` 返回的是「AI 简报文本」，不是文章列表；`normalize()` 拿不到 url/title 全部丢弃 → items 恒为空 |

第 3 条是致命的：即使桌面在线，只要 `info.brief` 返回的是简报而非 items，列表页就是空白。

### 1.2 修复方案：手机端自建抓取

不再依赖桌面后端，手机直接抓新闻源。

**关键实现 —— 绕开 CORS：**

新闻源不返回 `Access-Control-Allow-Origin`，WebView 里 `fetch` 会被拦。
新增原生方法 `SiyiNative.httpFetch`（`SiyiNativePlugin.kt`）：

```kotlin
@PluginMethod
fun httpFetch(call: PluginCall) { /* HttpURLConnection 在工作线程执行 */ }
```

- 走系统网络栈 → **系统级 VPN（星辰）开启后自动经 VPN 出口，无需任何植入**
- 支持 gzip 解压、3MB 上限、自定义 headers、字符集识别
- 结果 `{ok, status, body, contentType, bytes}`

**14 个源（实测可抓）：**

| 区域 | 源 | 实测 item 数 |
|---|---|---|
| 国内 | 36氪 / IT之家 / 爱范儿 / 少数派 / Solidot / InfoQ中文 / 开源中国 | 30 / 60 / 20 / 少 / 20 / 20 / 50 |
| 国际 | Hacker News / TechCrunch / Ars Technica / The Verge / Dev.to / Lobsters / MIT Tech Review | 20 / 20 / 20 / 10 / 12 / 25 / 10 |

**已剔除的源**（实测不可用，避免每次刷新报错噪音）：
- 机器之心 `jiqizhixin.com/rss` → 0 item
- arXiv `export.arxiv.org/rss/cs.AI` → 0 item；`rss.arxiv.org` → 407 需认证

**架构调整**：桌面端从「唯一数据源」降级为「补充源」，本地抓取是主路径。

**VPN 说明**：Android 的系统级 VPN 是全局的，App 无需任何配置。抓取失败时会提示「境外源不通，试试开启 VPN」而不是干巴巴报错。

## 二、笔记编辑器：对标小米笔记

### 2.1 改动前后

| | 之前 | 现在 |
|---|---|---|
| 工具栏 | 8 个纯 Markdown 文本按钮 | **6 图标一级条 + 9 个格式按钮二级条** |
| AI | 无 | **6 种写作动作** |
| 交互 | 只能插入语法 | 语法切换语义（再次点击取消）+ AI 结果可替换/追加 |

### 2.2 一级工具栏（对齐小米笔记的 6 图标）

```
✨ AI 辅助 | 🎙 语音 | 🖼 图片 | ☑ 待办清单 | T 文字格式 | ⋯ 更多
```

AI 按钮用强调色凸显，有选中文本时显示小红点提示「可对选中内容操作」。

### 2.3 AI 写作助手（`NoteAiAssistant.tsx`）

六个动作，覆盖写作中最高频的求助：

| 动作 | 行为 |
|---|---|
| 改写 | 换说法保持原意 |
| 续写 | 接着往下写 |
| 摘要 | 提炼要点 |
| 润色 | 修语病、提可读性 |
| 翻译 | 中英互译 |
| 提取待办 | 从文中抽可执行项为 `- [ ]` 列表 |

**交互设计**：AI 结果先展示，用户可选「替换选中 / 替换整篇 / 追加末尾」，不直接改写原文。

**隐私**：复用敏感词判定，含「密码/密钥/token」等内容直接拒绝并提示，不上传。

### 2.4 格式能力

支持加粗、斜体、标题、无序/有序列表、待办项、引用、代码块、分割线。
块级格式**多行选中时逐行加前缀**，再次点击取消 —— 这是小米笔记也有的体验。

## 三、待办：从「记目标」到「AI 自动化」

### 3.1 原来的水平

只有 `tryAutoCreateTask()` —— 把一句话解析成「标题+时间+优先级」的单个任务。
**那只是语音转表单，不是自动化。**

### 3.2 新增四个能力（`aiTaskEngine.ts`）

| 能力 | 作用 |
|---|---|
| **breakdown** | 把模糊目标拆成 6 个以内可执行子任务，带顺序、耗时、依赖 |
| **plan** | 给现有待办排今日时间表，考虑优先级/截止/精力，预留 30% 缓冲 |
| **triage** | 积压分诊：该做 / 推迟 / 删除 / 合并，带理由 |
| **nextAction** | 针对单个任务给出「现在就能做的第一个动作」 |

### 3.3 UI 入口

待办页顶部新增三个快捷按钮：`✨ 拆解目标` `🗓 安排今日` `🧹 清理积压`

**重要设计取舍**：AI 结果**一律先展示、后应用**，不直接写库。
- 拆解出的子任务默认全选，用户可勾选后批量创建
- 分诊建议只展示，删除决定权留给用户

自动化再聪明也不能替用户做删除决定。

### 3.4 健壮性

AI 返回的 JSON 用 `extractJson()` 容错解析（模型常包 ` ```json ` 或带前言）。
解析失败时给安全默认值（如把原目标变成一个任务），**不让 AI 的不稳定拖垮 UI**。

## 五、遗留问题（需要你决策）

1. **AI 功能都依赖云 AI Key**。笔记助手、待办自动化、资讯简报都需要在 设置 → AI 配置 里填 API Key 才能用。没配 Key 时按钮会给出明确提示，不会静默失败。

2. **境外源需要 VPN**。国内源（36氪、IT之家等 7 个）不需要；国际源（HN、TechCrunch 等 7 个）在国内直连会超时，需开系统级 VPN。抓取失败时会提示这一点。

3. **36氪偶发反爬**。实测连续 3 次正常，但历史上出现过返回 HTML 反爬页的情况。已做容错（解析不出条目时报「源格式可能变了」而不是崩溃）。

4. **笔记编辑器没有富文本**。当前是 Markdown + 预览切换，不是小米笔记那样的所见即所得。做真正的富文本需要引入编辑器库（Tiptap/Lexical），改动量大，需要你确认要不要做。
