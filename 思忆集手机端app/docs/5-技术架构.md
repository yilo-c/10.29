# 思忆便签 · 技术架构

## 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 外壳 | Capacitor 4+ | 原生壳，非 PWA。iOS + Android |
| UI 框架 | React 18 | 函数组件 + Hooks |
| 语言 | TypeScript 5 | 严格模式 |
| 状态管理 | Zustand | 与桌面端共享 store |
| 构建 | Vite 5 | 快速开发 + 构建 + 构建变体 |
| 样式 | 纯 CSS 自定义属性 | 无 Tailwind、无 CSS-in-JS |
| 测试 | Vitest | 单元测试 |
| 历法引擎 | lunar-javascript + 自研 | 黄历/八字/择日/奇门 — 独立算法实现，不依赖第三方 API |

## 数据流

### 状态管理

```
UI 组件
  → 调用 store actions（同步更新 Zustand state）
    → Zustand persist 中间件自动写入 localStorage
      → App 重新加载时 persist 自动恢复
```

没有网络请求、没有 API 调用（除 AI 辅助外），所有数据在本地闭环。

### 提醒调度

```
App.tsx（根组件）
  → 挂载时启动 useReminderScheduler
    → 每 30 秒扫描 todos 中 reminderTime 到期的项
    → 忽略已 snooze 未到期的项
    → 触发 ReminderBar + Notification + Audio
```

### 主题同步

```
SettingsView 调用 setTheme(t)
  → store 更新 theme 字段
  → App.tsx useEffect 检测变化
  → document.documentElement.setAttribute('data-theme', t)
  → CSS 自定义属性根据 data-theme 选择器切换
  → 所有组件自动响应（因引用 CSS 变量）
```

## 云端同步架构（V2）

### 设计原则

| 原则 | 说明 |
|------|------|
| 本地优先 | 用户即使不联网也能使用全部本地功能。同步是增值，不是依赖 |
| 无冲突设计 | 每条记录有 `updatedAt`，采用 last-write-wins，不引入复杂 CRDT |
| 最小传输 | 仅同步结构化数据（todos、notes、settings），不含运行时状态 |
| 端到端加密 | 服务器不存储明文数据，加解密在客户端完成 |
| 轻量后端 | 初期云函数 + 简易数据库，无需维护服务器 |

### 整体架构

```
┌──────────────┐         ┌──────────────────┐         ┌──────────────┐
│  手机端       │         │  云端 API         │         │  桌面端       │
│  React App   │ ◄─────► │  云函数计算       │ ◄─────► │  Electron    │
│  Zustand     │  HTTPS  │  (无状态)         │  HTTPS  │  Zustand     │
│  localStorage│         │  + 数据库          │         │  store.json  │
└──────────────┘         └──────────────────┘         └──────────────┘
```

### API 设计（极简，仅 4 个接口）

```
POST /v1/auth/login          — 手机号验证码 / 微信登录 → token
POST /v1/sync/upload         — 上传本地变更（增量）
POST /v1/sync/download       — 下载远端变更（增量）
POST /v1/sync/reset          — 全量覆盖（换机/恢复场景）
```

### 数据模型

```
// 服务端存储结构
interface SyncRecord {
  userId: string
  collection: 'todos' | 'notes' | 'categories' | 'settings'
  recordId: string
  data: string              // 加密后的 JSON
  checksum: string          // SHA-256 校验
  updatedAt: number         // 客户端时间戳
  createdAt: number
}
```

### 同步流程

```
手机端同步流程：
  1. 检查本地 store 中所有记录的 updatedAt
  2. 找出 lastSyncTime 之后有变动的记录
  3. POST /sync/upload 发送增量
  4. POST /sync/download?since={lastSyncTime} 拉取远端变更
  5. 逐条比较 updatedAt，取较新版本
  6. 写入本地 store → persist 自动持久化
  7. 更新 lastSyncTime

冲突策略：
  - 每条记录有 updatedAt（毫秒时间戳）
  - 同一条记录在两端同时修改 → 取 updatedAt 较新者
  - 极端情况（updatedAt 完全相同）→ 取 recordId 字典序较大者
  - 不引入解决冲突的 UI（用户无感知）
```

### 加密方案

```
客户端（上传前）：
  input → AES-256-GCM 加密 → base64 → 上传

服务端：
  只存密文，不存密钥，不读明文

密钥派生：
  masterKey = PBKDF2(userPasswordOrToken, salt, 100000 iterations)
  每条记录独立 nonce（12 字节随机数）
```

### 数据库表

```sql
-- 极简设计，仅 2 张表
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  phone TEXT UNIQUE,
  wechat_openid TEXT UNIQUE,
  pro_expires_at INTEGER,
  created_at INTEGER DEFAULT (unixepoch())
);

CREATE TABLE sync_data (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  collection TEXT NOT NULL,    -- 'todos' | 'notes' | 'categories' | 'settings'
  record_id TEXT NOT NULL,
  data TEXT NOT NULL,          -- 加密后的数据
  checksum TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  created_at INTEGER DEFAULT (unixepoch()),
  UNIQUE(user_id, collection, record_id)
);
CREATE INDEX idx_sync_lookup ON sync_data(user_id, collection, updated_at);
```

### 技术选型方案

| 目标市场 | 推荐方案 | 月成本估算 |
|---------|---------|-----------|
| 中国用户优先 | 阿里云函数计算 + TableStore / PolarDB | ¥10-50/月（1000 付费用户） |
| 海外用户 | Cloudflare Workers + D1 (SQLite) | $5-10/月（1000 付费用户） |
| MVP 验证期 | 同上任意一种即可，API 签名保持一致方便迁移 | — |

### 实现节奏

```
Phase 1（2-3 天）：
  - 云函数 4 个 API 接口实现
  - 手机端设置页加"登录"（手机号验证码 / 微信登录）
  - Zustand 同步 hook（useCloudSync）
  - Pro 开关：免费用户无法进入同步功能

Phase 2（追加）：
  - 桌面端同步接入（已有 store.json 映射到 sync 接口）
  - 端到端加密
  - WebSocket 实时同步（桌面端改了手机端秒收）

Phase 3（增长）：
  - 家庭共享（一套 Pro 多人使用）
  - 数据导出/备份（降低付费心理门槛）
  - 同步冲突历史查看（高级用户工单需求）
```

## 构建变体策略

同一套代码，通过构建时环境变量控制功能开关，以适配不同市场和审核需求：

```typescript
// vite.config.ts — 构建时功能开关
define: {
  __FEATURE_REFERENCE__: JSON.stringify(process.env.VITE_FEATURE_REFERENCE ?? 'true'),
  __FEATURE_BAZI__: JSON.stringify(process.env.VITE_FEATURE_BAZI ?? 'true'),
  __FEATURE_COMPASS__: JSON.stringify(process.env.VITE_FEATURE_COMPASS ?? 'true'),
}
```

| 构建变体 | 开关配置 | 用途 |
|---------|---------|------|
| `full` | 全部启用 | 官网直接分发、TestFlight |
| `store-safe` | 八字和罗盘默认关闭，需用户手动开启 | 国内安卓市场审核 |
| `minimal` | 仅保留日历 + 待办 | App Store 首次审核（确保通过后再加功能） |

**设计意图**：不在代码层面写死功能取舍。同一套代码库、同一个 Git 历史，通过构建配置输出不同版本。这样既能通过审核，又不需要维护多个分支。

## Capacitor 集成

### 使用的插件

| 功能 | 插件 |
|------|------|
| 传感器（罗盘） | 无需插件，用 Web DeviceOrientation API（Capacitor WebView 已支持） |
| 系统通知 | Notification API（Web，Capacitor 透明代理） |
| 生物识别 | `@capacitor/camera`（可选）或 WebAuthn（PWA 通用方案） |
| 文件导出 | `@capacitor/filesystem` |
| 应用退出 | `@capacitor/app`（监听 appStateChange 锁定） |
| 分享 | Web Share API（Capacitor 已支持） |

## 构建与发布

### 开发

```bash
cd packages/mobile
npm run dev          # Vite 开发服务器 (localhost:5173)
npm run typecheck    # TypeScript 检查
npm run test         # Vitest 单元测试
```

### 构建

```bash
npm run build                    # Vite 构建
npx cap add ios                  # 添加 iOS 工程
npx cap add android              # 添加 Android 工程
npx cap copy                     # 同步 Web 构建到原生工程
npx cap open ios                 # 在 Xcode 中打开
npx cap open android             # 在 Android Studio 中打开
```

### 发布

1. 构建 Web 资源：`npm run build`
2. 同步到原生工程：`npx cap copy`
3. 在 Xcode / Android Studio 中签名并发布
4. 或使用 `npx cap sync` 同步依赖后通过 CI 构建
