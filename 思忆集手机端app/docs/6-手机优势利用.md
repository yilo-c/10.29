# 思忆便签 · 手机优势利用

> 从 PWA 到 Capacitor 原生壳后，不再受浏览器沙箱限制。本文档列出手机端独有的能力及其在产品中的具体应用。

---

## 手机优势 = 决策辅助的护城河

以下能力不是"手机比桌面多什么功能"，而是**为什么手机端思忆便签在决策辅助这个定位上，比桌面端和纯 Web 竞品有不可替代的优势**：

| 能力 | 对定位的贡献 |
|------|------------|
| 罗盘传感器 | 实时方位参考——桌面端用不了，Web 端不准。这是竞品最难复制的差异化 |
| 系统通知 + 本地通知 | 提醒是"决策辅助"的直接体现——在正确的时间告诉用户该做什么 |
| 触感反馈 | 让"滑动完成待办"有物理实感，提升工具品质感（不是命理功能，是效率功能） |
| 生物识别 | 保护用户的出生信息——隐私是思忆便签的核心承诺 |
| 原生分享 | 把今日宜忌分享给朋友/家人——这是自然增长的主要入口 |
| 屏幕常亮 | 罗盘使用时保持常亮——让传感器功能真正可用 |
| 应用角标 | 今日未完成待办数量——把用户拉回 App 的信号，跟命理无关 |
| 小组件 | V2 在桌面显示今日宜忌——不打开 App 就能获得参考信息，这是"日历工具"的核心体验 |

**关键认识**：手机端的传感器和通知能力，让思忆便签从"一个可以查黄历的 App"升级为"一个在你需要的时候主动出现的决策参考"。这种从被动到主动的转变，是手机端相对桌面端最根本的差异化。

## 1. 传感器

### 罗盘（磁力计）

**桌面端限制**：大部分桌面设备无磁力计，罗盘功能不可用。
**手机端利用**：几乎所有智能手机都有磁力计。

**产品应用**：
- 参考页的方位罗盘卡实时显示设备朝向
- 对比今日喜神/财神/福神方位，朝向一致时高亮提示
- 用户无需手动输入方向，打开卡片即知

**实现**：`shared/hooks/useCompass.ts` 已封装好 iOS 权限请求（需要用户手势触发）和 Android 自动启动。通过 `requestAnimationFrame` 做 1° 节流。

### 振动器

**桌面端限制**：桌面设备极少有振动马达。
**手机端利用**：所有手机均有振动马达。

**产品应用**：
- Tab 切换、按钮点击、待办操作的全套触感反馈（详见交互规范）
- 提醒触发时配合闹铃振动

**实现**：`navigator.vibrate(ms)`，在桌面端静默失败。

## 2. 系统通知

**桌面端限制**：PWA 在桌面端的通知支持有限，且用户很少允许。
**手机端利用**：手机 App 的通知是用户期望的核心功能。

**产品应用**：
- 待办提醒到点时在通知栏显示（含待办文字）
- App 关闭 / 后台时也能收到提醒

**实现**：Notification API。App 启动时请求权限。配合前台的 Web Audio 闹铃实现双重保障。

### 对比：为什么不是系统闹钟

| | 本地通知 | 系统闹钟 |
|--|---------|---------|
| iOS | ✓ 支持 | ❌ 第三方 App 无法创建系统闹钟 |
| Android | ✓ 支持 | Intent 方式但体验差（跳转弹窗） |
| 关闭 App 后 | ✓ 仍可触发（操作系统托管） | ✓ 可靠 |
| 自定义铃声 | ✓ | ❌ |

**结论**：使用本地通知（Local Notifications），通过 Capacitor 的 Local Notifications 插件（或直接使用 Web Notification API）。Android 上通知可以做到准时、可靠；iOS 上通知中心即可满足提醒需求。不追求"系统闹钟"集成。

---

## 3. 生物识别

**桌面端限制**：Windows Hello / Mac Touch ID 可以但使用率低。
**手机端利用**：面容 ID / 指纹是手机标配，用户习惯用它们保护敏感 App。

**产品应用**：
- 启动 App 时验证身份（需用户在设置中开启）
- 切换到后台再回来时自动锁定
- 失败 5 次后增加延迟

**实现**：WebAuthn API 或 Capacitor 的 `@capacitor/biometric` 插件。前者不需要原生依赖，后者更稳定。

---

## 4. 原生分享

**桌面端限制**：PWA 不支持原生分享菜单。
**手机端利用**：用户期待点击"分享"能发送到微信、邮件等。

**产品应用**：
- 笔记卡片右侧分享按钮
- 分享内容：笔记标题 + 正文

**实现**：`navigator.share({ title, text })`。Capacitor WebView 自动代理到系统分享菜单。在桌面端 fallback 到复制到剪贴板。

---

## 5. 关闭 App 后的行为

**桌面端限制**：PWA 关闭后所有定时器失效。
**手机端利用**：原生 App 可以通过本地通知在关闭后仍触发提醒。

**产品应用**：
- 待办提醒在 App 关闭后仍可通过通知触达用户
- App 挂起到后台不杀进程（Capacitor 提供保活）

**实现**：Capacitor Local Notifications 插件在 Android 上使用 AlarmManager，iOS 上使用 UNNotificationRequest。即使 App 被系统杀掉，通知仍能在预定时间触发。

---

## 6. 应用图标角标

**桌面端限制**：PWA 不支持角标。
**手机端利用**：原生 App 可以显示未完成待办数量的角标。

**产品应用**：
- 主屏幕图标上显示今日未完成待办数量
- 用户无需打开 App 就知道还有多少事要做

**实现**：Capacitor 的 Badge 插件（`@capacitor/badge`），在每个待办操作后更新角标数字。

---

## 7. 小组件（Widget）

**桌面端限制**：PWA 不支持主屏幕小组件。
**手机端利用**：Android 和 iOS 都支持原生小组件。

**产品应用**（V2）：
- 主屏幕小组件显示今日日期 + 黄历宜忌简略
- 用户不打开 App 就能看到"今天适不适合"的关键信息

**实现**：Android 用 `@capacitor/widget` 或原生 App Widget；iOS 用 WidgetKit（需 Swift 代码）。属于 V2 增强范围。

---

## 8. 启动屏（Splash Screen）

**桌面端限制**：PWA 白屏或简单纯色。
**手机端利用**：原生启动屏是品牌第一印象。

**产品应用**：
- 品牌 Logo + 应用名称 + "决策辅助工具"副标题
- 深色背景 + 金色 Logo（匹配品牌色）
- 平滑过渡到主界面

**实现**：Capacitor 内置 SplashScreen 插件，配置图像和背景色即可。

---

## 9. 屏幕常亮

**桌面端限制**：不需要（桌面本身不熄屏）。
**手机端利用**：阅读参考/罗盘时保持屏幕常亮。

**产品应用**：
- 用户在参考页阅读长篇黄历/八字内容时屏幕不自动熄屏
- 罗盘页使用时保持常亮

**实现**：`navigator.wakeLock.request('screen')`（Screen Wake Lock API）。用户离开页面后自动释放。

---

## 10. 触感与声音的综合提醒体验

这是手机端相对于桌面端最强的差异化体验：

**桌面端**：振动可有可无，通知在通知中心，用户不一定看。
**手机端**：

1. 到点 → 振动唤醒手机
2. 通知出现在锁屏界面（亮屏）
3. 如果 App 在前台 → 音频闹铃 + 视觉 ReminderBar
4. 如果 App 在后台 → 本地通知推送
5. 用户操作：滑动关闭 / 点击稍后提醒

多通道同时触达，确保用户不会错过重要提醒。这是"手机原生"的核心价值之一。
